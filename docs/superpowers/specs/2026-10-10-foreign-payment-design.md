# 해외 결제 · 환율 설계

작성: 2026-10-10 · 고침: 2026-10-10(카드사와 관계없이 통화 표시를 읽고 해외 결제도 자동 기록) · 상태: 사용자 승인(대화, "이대로 설계 문서 고쳐줘").

**왜**: 해외 결제 문자(예: KB국민카드 "해외승인 8.00(USD)")는 지금 휴대폰 거르기·서버 분석·붙여넣기 어디서도 금액을 못 읽는다. 원화가 아니라 그대로는 한도·쓴 돈에 넣을 수 없다.

**잘 됐다고 볼 기준**: 잠긴 아이폰에서 국민카드·현대카드로 해외 결제를 하면 손대지 않아도 `약 1만 739원 · 8.00 USD`로 장부에 들어오고 한도에 반영된다.

**사용자 결정**
- 해외 결제도 국내 결제처럼 자동 기록한다.
- 카드사와 관계없이 문자에 통화 표시(USD·EUR·JPY·VND 등)가 있으면 환율로 원화를 계산해 보여 준다.
- 문자에 `원` 금액이 있으면 원화를 그대로 쓴다(카드사가 이미 원화로 바꿔 보낸 경우).
- 현대카드 해외 문자는 예시가 없지만 국민카드와 같은 줄 배치로 보고 진행한다.
- 환율은 인증키 없는 무료 API(open.er-api.com)에서 받는다(네이버는 robots.txt가 자동 수집을 막아 쓰지 않는다).
- 해외 이용 수수료는 넣지 않고 환율만 쓴다.
- 환율은 매일 **오전 9시 10분(KST)** 에 받는다(이 API는 한국 시간 오전 9시쯤 갱신).
- 해외 결제는 카드 문자 거래여도 **금액을 고칠 수 있다**(명세서의 실제 청구액으로).

## 1. 통화 금액 읽기 (공통)

새 공통 부분 `src/parsers/money.ts`. 카드사 분석기·확인할 문자 미리 채우기·붙여넣기가 모두 이것을 쓴다.

- 돌려주는 것: 원화 `{ currency: "KRW", amount }` 또는 외화 `{ currency, foreignAmount }`. 못 찾으면 없음.
- 읽는 표시:

| 표시 | 예 | 통화 |
|---|---|---|
| 숫자 + `원` | `12,300원` | 원화 |
| 3글자 코드(앞·뒤, 괄호 있어도 됨) | `8.00(USD)`, `USD 8.00`, `1,234.50 EUR` | 그 코드 |
| `$`, `달러` | `$8.00`, `20달러` | USD |
| `€`, `유로` | `€12.50`, `12.5유로` | EUR |
| `¥`, `엔` | `¥1500`, `1,500엔` | JPY |
| `£`, `파운드` | `£9.99` | GBP |
| `위안` | `30위안` | CNY |
| `동` | `150,000동` | VND |

- 3글자 코드는 코드에 고정한 ISO 통화 코드 목록에 있는 것만 인정한다(아무 대문자 3글자를 통화로 보지 않는다). 목록에는 있지만 그날 환율이 없는 통화는 3절대로 확인할 문자로 간다.
- 문자에 3글자 코드가 함께 있으면 기호·한글보다 코드를 따른다(예: `$`와 `CAD`가 같이 있으면 CAD).
- `동`은 주소("123동")와 헷갈리지 않게 숫자 바로 뒤에 붙고, 같은 문자에 `승인` 또는 `취소`가 있을 때만 통화로 본다.
- **원화 우선**: `원` 금액이 있으면 원화로 돌려준다. 외화 표시가 같이 있으면 참고용으로 함께 돌려준다(저장만 하고 계산에는 안 씀).
- 누적 금액 줄(`누적`)은 건너뛴다(지금 규칙과 같음).
- 소수점·쉼표 자리 구분을 읽는다. 엔·동처럼 소수가 없는 것도 읽는다.

## 2. 카드 문자 분석 (국민·현대)

- 국민카드·현대카드 분석기는 첫 줄에 `해외승인`/`해외취소`가 있거나 외화 금액이 있으면 해외 형식으로 읽는다.
- 국민카드 해외 형식(사용자 제공 예시, 카드번호·이름은 가상):

```
[Web발신]
KB국민카드1234 해외승인
8.00(USD) 10/02 09:08
미국 typesafe a
```

- 꺼내는 것: 종류(해외승인 → 결제, 해외취소 → 취소), 통화, 외화 금액, 시각(`MM/DD HH:mm`, 연도는 지금처럼 받은 시각으로 추정), 가게.
- 가게: 시각이 있는 줄의 다음 줄. 앞에 나라 이름이 붙어 있으면(`미국 typesafe a`) 첫 단어를 나라로 떼고 나머지를 가게로 쓴다. 나라는 저장하지 않는다.
- 현대카드 해외 형식은 예시가 없어 국민카드와 같은 배치(머리 줄 `해외승인`, 통화 금액, 시각, 가게)로 읽는다. 금액·시각·가게 중 하나라도 못 찾으면 지금처럼 확인할 문자로 간다.
- 해외취소 형식도 예시가 없어 해외승인과 같은 배치로 가정한다.
- 분석 결과(`ParseResult`)에 `currency`, `foreignAmount`를 더한다. 원화 결제는 지금과 같다.
- 그 밖의 카드사는 분석기가 없으므로 지금처럼 확인할 문자로 간다. 확인할 문자의 [거래로 등록] 미리 채우기(`src/ledger/sms-guess.ts`)와 붙여넣기(`src/ledger/paste-sms.ts`)는 1절의 공통 읽기를 써서, 외화면 예상 원화를 금액 칸에 넣고 "8.00 USD를 결제일 환율로 계산했어요"를 보여 준다.

## 3. 원화 금액

- 예상 원화 = 외화 금액 × 결제 날짜(KST)의 저장된 환율, 원 단위 반올림. 수수료는 넣지 않는다.
- 결제 날짜의 환율이 없으면 그 이전 가장 가까운 날짜의 값을 쓴다. 저장된 환율이 하나도 없으면 그 자리에서 한 번 받아 저장한 뒤 계산한다. 그래도 실패하면 거래는 확인할 문자로 보낸다(원화를 모르는 채 장부에 넣지 않는다).
- 예상 원화는 한도·쓴 돈·분류별 합계에 그대로 들어간다.
- 화면:
  - 목록 줄: `약 1만 739원` 아래 작은 글씨 `8.00 USD`
  - 거래 상세: 금액 `약 10,739원 (예상)`, 그 아래 `8.00 USD × 1,342.34원 (10월 2일 환율)`, 맨 아래 작은 글씨 `환율 제공: ExchangeRate-API`
- 금액 고치기: 해외 결제는 카드 문자 거래여도 상세의 금액 항목을 누를 수 있다. 실제 청구액으로 저장하면 "예상"과 "약"이 사라지고 외화·환율 줄은 남는다. 가게·일시·사람은 지금처럼 고칠 수 없다.
- 해외 취소: 같은 사람·같은 통화·같은 외화 금액의 해외 결제와 짝을 짓고, 원화는 짝지은 결제의 지금 원화 금액(고쳤으면 고친 값)을 음수로 쓴다. 짝이 없으면 취소 날짜 환율로 계산한다.

## 4. 환율 받기

- 가계부 앱(NAS의 app 컨테이너)이 켜져 있는 동안 매일 09:10 KST에 `https://open.er-api.com/v6/latest/KRW`(또는 USD 기준을 역산)에서 환율을 받아 날짜별로 저장한다. 날짜는 API의 갱신 시각(`time_last_update_utc`)을 KST로 바꾼 날.
- 새 컨테이너나 따로 도는 작업을 만들지 않는다. 앱이 켜질 때 함께 시작되는 Next.js 기능(`instrumentation.ts`)으로 타이머를 건다. 이 판의 Next.js 안내(`node_modules/next/dist/docs/`)를 계획 단계에서 확인한다.
- 앱이 켜질 때 오늘 환율이 없으면 한 번 받는다(NAS 재시작·새 판 교체 대비).
- 저장하는 통화: API가 주는 전체(약 166개). 하루 한 줄(JSON)이라 양이 작다.
- 실패(응답 없음·형식 다름)하면 저장하지 않고 다음 날 다시 받는다. 마지막 성공 날짜가 2일 이상 지나면 운영자 화면에 "환율 갱신 실패(마지막 YYYY-MM-DD)"를 보인다.
- NAS 사용량 제한(4번째 코어·메모리 상한)은 그대로다.

## 5. DB 변경

- `transactions`에 칸 추가: `currency text`(외화일 때 3글자, 원화면 null), `foreign_amount numeric`, `fx_rate numeric`(적용 환율), `amount_estimated boolean not null default false`.
- 새 표 `fx_rates(date date primary key, base text, rates jsonb, fetched_at timestamptz)`. 읽기는 로그인한 사용자, 쓰기는 서비스 키만.
- 카드 거래 보호 규칙(`20261008020000_card_tx_guard`)을 고친다: 카드 거래의 금액 변경은 거절하되 `currency is not null`(해외 결제)이면 허용. 금액을 고치면 `amount_estimated = false`.
- `ingest_sms`에 외화 칸(통화·외화 금액·환율·예상 여부)을 넘기는 인자를 더한다. 원화 계산은 서버(앱)에서 하고 DB 함수는 받은 값을 저장한다.

## 6. 휴대폰 거르기와의 관계

- 휴대폰 연결 다시 설계(자동화 하나, 단축어 안 정규식)에서 쓸 거르기 규칙은 금액을 `숫자원` 또는 1절의 외화 표시(3글자 코드·기호·한글)로 본다. 그 작업에서 함께 반영한다(이번 범위 밖).

## 7. 검사

- 단위: 통화 읽기(코드 앞·뒤·괄호, 기호, 한글, 코드 우선, `동`과 주소 구분, 원화 우선, 누적 건너뛰기, 쉼표·소수·정수), 국민·현대 해외 분석(나라/가게 나누기, 해외취소), 예상 원화 계산(반올림, 이전 날짜 환율, 환율 없음), 확인할 문자 미리 채우기·붙여넣기 결과.
- DB: 해외 결제 저장(외화 칸·예상 표시), 금액 고치기 허용(해외만)·국내 카드 거래는 여전히 거절, 해외 취소 짝짓기, `fx_rates` 권한.
- 화면: 목록 `약 …원 · 8.00 USD`, 상세 환율 줄과 출처, 금액 고친 뒤 "예상" 사라짐, 붙여넣기 해외 문자.
- 환율 받기: API 응답 견본으로 저장, 실패 시 저장 안 함, 앱 켜질 때 오늘 값 없으면 받기, 2일 경과 표시.

## 하지 않는 것

- 해외 이용 수수료 계산(사용자 결정).
- 국민·현대 외 카드사의 자동 기록(분석기가 없어 확인할 문자 + 원화 미리 채우기까지).
- 휴대폰 연결 다시 설계(자동화 하나·단축어 정규식) — 별도 작업.

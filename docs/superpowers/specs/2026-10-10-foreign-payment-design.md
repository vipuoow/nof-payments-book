# 해외 결제 · 환율 설계

작성: 2026-10-10 · 상태: 사용자 승인(대화, "2~4번 먼저 문서로 써줘"). 휴대폰 연결 다시 설계(자동화 하나)는 잠금 상태 시험 뒤 별도 문서로 쓴다.

**왜**: 해외 결제 문자(예: KB국민카드 "해외승인 8.00(USD)")는 지금 휴대폰 거르기·서버 분석·붙여넣기 어디서도 금액을 못 읽는다. 원화가 아니라 그대로는 한도·쓴 돈에 넣을 수 없다.

**사용자 결정**
- 원화는 자동 계산한다. 환율은 인증키 없는 무료 API(open.er-api.com)에서 받는다(네이버는 robots.txt가 자동 수집을 막아 쓰지 않는다).
- 해외 이용 수수료는 넣지 않고 환율만 쓴다.
- 환율은 매일 **오전 9시 10분(KST)** 에 받는다(이 API는 한국 시간 오전 9시쯤 갱신).
- 해외 결제는 카드 문자 거래여도 **금액을 고칠 수 있다**(명세서의 실제 청구액으로).

## 1. 해외 결제 문자 읽기

국민카드 형식(사용자 제공 예시, 카드번호·이름은 가상):

```
[Web발신]
KB국민카드1234 해외승인
8.00(USD) 10/02 09:08
미국 typesafe a
```

- 꺼내는 것: 종류(해외승인 → 결제, 해외취소 → 취소), 통화(`USD`), 외화 금액(`8.00`), 시각(`10/02 09:08`, 연도는 지금처럼 받은 시각으로 추정), 나라(`미국`), 가게(`typesafe a`).
- 외화 금액 형식: `숫자(.숫자)?` 뒤에 `(통화 3글자)`. 쉼표 자리 구분(`1,234.50(EUR)`)도 읽는다. 엔화처럼 소수가 없는 것(`1500(JPY)`)도 읽는다.
- 해외취소 문자 형식은 예시가 없어 해외승인과 같은 줄 배치로 가정한다. 다르면 확인할 문자로 가고, 예시가 생기면 고친다.
- 현대카드 해외 문자는 예시가 생기면 더한다(이번 범위 밖).
- 붙여넣기(`readPastedSms`)도 같은 분석기를 쓴다. 붙여넣기의 마지막 화면 금액 칸에는 예상 원화가 들어가고, 위 안내에 "8.00 USD를 오늘 환율로 계산했어요"를 보여 준다.
- 휴대폰 거르기(휴대폰 연결 다시 설계에서 쓸 규칙)는 금액을 `숫자원` 또는 `숫자(통화)`로 본다.

## 2. 원화 금액

- 예상 원화 = 외화 금액 × 결제 날짜(KST)의 저장된 환율, 원 단위 반올림. 수수료는 넣지 않는다.
- 결제 날짜의 환율이 없으면 그 이전 가장 가까운 날짜의 값을 쓴다. 저장된 환율이 하나도 없으면 거래는 확인할 문자로 보낸다(원화를 모르는 채 장부에 넣지 않는다).
- 예상 원화는 한도·쓴 돈·분류별 합계에 그대로 들어간다.
- 화면:
  - 목록 줄: `약 1만 739원` 아래 작은 글씨 `8.00 USD`
  - 거래 상세: 금액 `약 10,739원 (예상)`, 그 아래 `8.00 USD × 1,342.34원 (10월 2일 환율)`, 맨 아래 작은 글씨 `환율 제공: ExchangeRate-API`
- 금액 고치기: 해외 결제는 카드 문자 거래여도 상세의 금액 항목을 누를 수 있다. 실제 청구액으로 저장하면 "예상"과 "약"이 사라지고 외화·환율 줄은 남는다. 가게·일시·사람은 지금처럼 고칠 수 없다.
- 해외 취소: 같은 사람·같은 통화·같은 외화 금액의 해외 결제와 짝을 짓고, 원화는 짝지은 결제의 지금 원화 금액(고쳤으면 고친 값)을 음수로 쓴다. 짝이 없으면 취소 날짜 환율로 계산한다.

## 3. 환율 받기

- 매일 09:10 KST, NAS의 가계부 앱이 `https://open.er-api.com/v6/latest/KRW`(또는 USD 기준을 역산)에서 환율을 받아 날짜별로 저장한다. 날짜는 API의 갱신 시각(`time_last_update_utc`)을 KST로 바꾼 날.
- 저장하는 통화: API가 주는 전체(약 166개). 하루 한 줄(JSON)이라 양이 작다.
- 실패(응답 없음·형식 다름)하면 저장하지 않고 다음 날 다시 받는다. 마지막 성공 날짜가 2일 이상 지나면 운영자 화면에 "환율 갱신 실패(마지막 YYYY-MM-DD)"를 보인다.
- 앱이 켜질 때 오늘 환율이 없으면 한 번 받는다(NAS 재시작·새 판 교체 대비).
- 실행 방법은 계획에서 정한다(앱 안 타이머 또는 NAS 백업 컨테이너처럼 따로 도는 작업). NAS 사용량 제한(4번째 코어·메모리 상한)을 지킨다.

## 4. DB 변경

- `transactions`에 칸 추가: `currency text`(외화일 때 3글자, 원화면 null), `foreign_amount numeric`, `fx_rate numeric`(적용 환율), `amount_estimated boolean not null default false`.
- 새 표 `fx_rates(date date primary key, base text, rates jsonb, fetched_at timestamptz)`. 읽기는 로그인한 사용자, 쓰기는 서비스 키만.
- 카드 거래 보호 규칙(`20261008020000_card_tx_guard`)을 고친다: 카드 거래의 금액 변경은 거절하되 `currency is not null`(해외 결제)이면 허용. 금액을 고치면 `amount_estimated = false`.
- `ingest_sms`에 외화 칸을 넘기는 인자를 더한다.

## 5. 검사

- 단위: 해외승인 분석(USD·EUR 쉼표·JPY 정수·나라/가게 나누기), 예상 원화 계산(반올림, 이전 날짜 환율, 환율 없음), 붙여넣기 결과.
- DB: 해외 결제 저장(외화 칸·예상 표시), 금액 고치기 허용(해외만) · 국내 카드 거래는 여전히 거절, 해외 취소 짝짓기, `fx_rates` 권한.
- 화면: 목록 `약 …원 · 8.00 USD`, 상세 환율 줄과 출처, 금액 고친 뒤 "예상" 사라짐, 붙여넣기 해외 문자.
- 환율 받기: API 응답 견본으로 저장, 실패 시 저장 안 함, 2일 경과 표시.

## 하지 않는 것

- 해외 이용 수수료 계산(사용자 결정).
- 현대카드 해외 문자(예시 생기면).
- 휴대폰 연결 다시 설계(자동화 하나) — 잠금 시험 뒤 별도 문서.

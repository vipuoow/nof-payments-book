# 같이가계부 디자인 1차 적용 설계

작성: 2026-10-07 · 상태: 사용자 승인(2026-10-07)

## 1. 목표

- 화면에 디자인을 입힌다.
- 처음 쓰는 사람이 "가입 → 가계부 만들기 → 파트너 초대 → 휴대폰 연결 → 한도 정하기 → 첫 결제"까지 헤매지 않게 한다.

**기준**
- 사용자가 정한 우선순위: 배우자가 쓰기 편하게 → 보여 주기 → 우리 집 개성 → 한눈에 파악
- 전체 기준: "가장 편하면서도 심플하고 깔끔하게"
- 배우자가 쓰는 장면: 가끔 훑어보기

**서비스 이름**
- 이름: **같이가계부**
- 부제: "카드만 써, 기록은 내가 할게"

**참고**
- 시안은 claude.ai 비공개 시안 페이지(15판)에 있다. 공개 저장소이므로 주소는 적지 않는다.
- 시안 파일 사본은 사용자 컴퓨터에 있다.

## 2. 범위

**이번에 하는 것**
1. 디자인 기준(색·글자·카드·말투) 적용
2. 처음 화면: 배경 영상, Google 로그인
3. 가계부 만들기와 닉네임
4. 파트너 초대와 초대 수락
5. 처음 홈 3단계: 휴대폰 연결 → 한도 정하기 → 홈
6. 한도 바꾸기
7. 휴대폰 연결 안내(아이폰·갤럭시)
8. 홈: 달 고르기, 금액 한 줄, 쓴 카드 표시, 연결 전 알림
9. 메뉴 정리
10. Google 로그인을 우리 화면에서 직접 받기
11. 배경 영상을 NAS 파일로 교체할 수 있게 하기

**이번에 하지 않는 것** (내일 따로 설계)
- 거래 상세, 직접 입력, 카테고리 관리, 확인할 문자 화면의 새 설계
- 이 화면들은 디자인 기준(색·글자)만 자동으로 따라간다.
- 운영자 화면은 바꾸지 않는다.

## 3. 디자인 기준 (시안 1번 "토스 느낌")

**색**
- 바탕: 연회색 `#f2f4f6`
- 카드: 흰색, 모서리 반경 20px
- 글자: `#191f28`, 보조 글자: `#6b7684`
- 강조: `#3182f6`, 강조 연한 바탕: `#e8f3ff`
- 경고: `#f04452`
- 다크 모드는 휴대폰 설정을 따른다. 바탕 `#101013`, 카드 `#1d1d22`, 강조 `#4b93f8`.
- 지금처럼 `globals.css`의 색 변수만 바꿔서 모든 화면에 퍼지게 한다.

**글자**
- 기기 기본 글꼴(Apple SD Gothic Neo 계열)을 그대로 쓴다.
- 숫자는 같은 폭으로(tabular) 맞춘다.

**말투**
- 친절한 해요체를 쓴다. 예: "1,284,500원 썼어요", "남았어요"
- 오류도 같은 말투로 쓰고, 고칠 방법을 함께 알려 준다. 예: "초대 링크가 만료됐어요. 초대한 가족에게 새 링크를 부탁해 주세요."

**배치**
- 주요 버튼은 화면 아래쪽, 엄지가 닿는 곳에 둔다.
- 화면 하나에는 할 일 하나만 둔다.

## 4. 화면 설계

### 4.1 처음 화면 (로그인 · 초대 링크로 들어온 화면)

**배경 영상**
- 화면을 꽉 채운다(`object-fit: cover`).
- 전체를 35% 어둡게 덮고, 위·아래는 조금 더 진하게 덮는다.

**영상 위 한 겹**
- 제목 "같이가계부"와 부제는 화면 높이의 30% 지점에 가운데를 맞춘다.
- Google 로그인 버튼과 안내 문구는 아래쪽에 둔다.

**끊김 없는 반복**
- `video` 요소 두 개를 겹쳐 둔다.
- 영상이 끝나기 0.6초 전에 다음 영상을 처음부터 재생하면서 서로 겹쳐 바꾼다(교차 전환).
- 화면에 보이지 않으면 멈춘다.

**동작 줄이기**
- 휴대폰의 '동작 줄이기' 설정이 켜져 있으면 영상을 재생하지 않는다.
- 대신 멈춘 그림(`landing.jpg`)을 보여 준다.

**초대 링크로 들어온 경우**
- 같은 화면을 쓰고, 버튼 위에 "{그룹장 닉네임}님이 같이가계부에 초대했어요" 한 줄을 더한다.

**오류 화면**
- 초대 링크가 만료·사용·취소됐거나 자리가 다 찬 경우에 보인다.
- 같은 모양으로 말만 바꾼다.

### 4.2 Google 로그인을 우리 화면에서 직접 받기

**문제**
- 지금은 Google 화면에 클라우드 로그인 주소(`<프로젝트>.supabase.co`)가 보인다.

**바꾸는 방식**
- Google Identity Services(GIS)로 우리 화면에서 Google 로그인 창을 띄운다.
- 받은 ID 토큰을 `supabase.auth.signInWithIdToken({ provider: "google", token, nonce })`로 넘겨 로그인한다.
- 이렇게 하면 Google 화면에는 우리 주소(`ledger.<도메인>`)가 보인다.

**재사용 공격 막기**
- 서버가 1회용 nonce를 만들어 둔다.
- Google에는 해시한 값을, Supabase에는 원래 값을 넘긴다.

**버튼**
- GIS가 그려 주는 공식 버튼을 쓴다(`renderButton`, 흰색, 한국어, "Google로 계속하기").
- Google 정책상 ID 토큰 방식은 공식 버튼을 써야 한다. 그래서 시안의 버튼과 글자는 조금 다를 수 있다.
- 사용자 결정: 모양은 분위기만 비슷하게 하되, **가로 폭·가운데 정렬·높이는 다른 버튼과 맞춘다.**

**안전한 전환**
- `GOOGLE_CLIENT_ID`가 비어 있으면 지금의 리디렉트 방식(`signInWithOAuth`)을 쓴다. 이때 버튼은 시안 모양(흰 바탕, 네 가지 색 G 로고)으로 직접 그린다.
- 값이 있으면 GIS 방식을 쓴다.
- 그래서 Google 콘솔 설정 전에 배포해도 로그인이 깨지지 않는다.

**설정**
- Google 클라이언트 ID는 실행할 때 환경값 `GOOGLE_CLIENT_ID`로 넣는다(서버에서 화면으로 전달). 이미지에 넣어 굽지 않는다.
- NAS의 `.env`와 `compose.yaml`에 추가한다.
- Google 콘솔의 "승인된 JavaScript 원본"에 `https://ledger.<도메인>`과 로컬 주소를 추가한다.
- Supabase Google 제공자의 허용 클라이언트 ID에 같은 ID를 넣는다.

**기존 코드 정리**
- `signInWithOAuth`와 `/auth/callback`은 바로 지우지 않고 남긴다.
- 새 방식이 운영에서 확인되면 지운다.

**운영에서 할 일**
- 적용 뒤 Google 브랜드(앱 이름·로고) 인증을 신청한다(사용자가 진행).

### 4.3 가계부 만들기와 닉네임

**닉네임 원칙**
- 두 사람의 닉네임은 **그룹장이 정한다.**
- 정한 뒤에는 **바꿀 수 없다**(바꾸는 화면을 만들지 않는다).
- 닉네임은 `profiles.display_name`에 저장한다.
- 거래 목록, 합계, 초대 문구 어디에나 이 닉네임을 쓴다.

**가계부 만들기 화면**
- 지금의 "그룹 없음"과 "그룹 만들기" 두 화면을 하나로 합친다.
- 인사는 "{Google 이름}님, 반가워요"로 한다.
- "내 닉네임"을 입력받는다(필수, 공백 제외 1~10자).
- 만들기를 누르면 그룹을 만들면서 내 `display_name`을 그 닉네임으로 바꾼다.

**만들 권한이 없을 때**
- 서비스 초대를 받지 않았으면 버튼 대신 "가족에게 초대 링크를 받아 주세요"를 보여 준다.

**서비스 초대 수락(운영자 → 그룹장)**
- 이제는 이름을 묻지 않는다.
- 프로필은 Google 이름으로 먼저 만들고, 가계부 만들기 화면에서 닉네임으로 바꾼다.

**바뀌는 DB 함수**
- `create_group()` → `create_group(p_display_name text)`: 그룹 만들기와 닉네임 저장을 한 번에 처리한다.
- `accept_invite`: 서비스 초대를 받을 때 이름이 비어 있으면 Google 이름을 쓴다(서버에서 넘김).

### 4.4 파트너 초대 (메뉴 "파트너 잡으러 가기")

**메뉴가 보이는 조건**
- 그룹장에게만 보인다.
- 그룹 인원이 최대(2명)보다 적을 때만 보이고, 파트너가 들어오면 사라진다.

**처음 쓰는 사람 흐름**
- 가계부를 만들면 바로 이 화면으로 온다.
- "나중에 할게요"를 누르면 처음 홈으로 간다.

**초대 순서**
- **초대할 가족의 닉네임**을 입력한다(필수).
- "초대 링크 만들기"를 누르면 링크를 만들고 바로 **휴대폰 공유 창**(`navigator.share`)을 띄운다.
- 공유 문구: "{그룹장 닉네임}님이 같이가계부에 초대했어요. 아래 링크로 가입해 주세요({만료일}까지)." 뒤에 링크를 붙인다.
- 공유 창이 없거나 거절되면 링크를 복사하고 "링크를 복사했어요"를 보여 준다.

**휴대폰 공유 창이 열리지 않는 경우 대비**
- 휴대폰 브라우저는 버튼을 누른 직후에만 공유 창을 연다.
- 그래서 링크를 만드는 동안 시간이 걸려 공유 창이 열리지 않으면, "카카오톡·문자로 보내기" 버튼을 한 번 더 보여 준다.
- 링크는 이 화면에서만 볼 수 있다.

**보낸 뒤 화면**
- "초대를 보냈어요" 화면으로 간다.
- 나중에 메뉴로 다시 들어와도 같은 모습(기다리는 중)이 보인다.

**상태별로 보이는 것**
| 상태 | 보이는 것 |
|---|---|
| 기다리는 중 | "{닉네임}님 초대를 기다리는 중 · {만료일}까지", [취소], [새 링크 만들어 다시 보내기] |
| 만료 | "{닉네임}님 초대 링크가 만료됐어요", [초대 링크 다시 만들기] |

**새 링크를 만들면 이전 링크를 자동으로 취소한다**
- 아직 쓰지 않았고 취소되지 않은 이전 링크가 대상이다.
- 링크는 다시 볼 수 없으니, 헷갈리지 않게 링크는 늘 하나만 살아 있게 한다.

**바뀌는 DB**
- `group_invites`에 `invitee_name text` 열을 더한다.
- `create_group_invite(p_token_hash, p_invitee_name)`: 닉네임을 저장하고 이전 링크를 취소한다.

### 4.5 초대 수락 (파트너)

**순서**
- 처음 화면(초대 문구) → Google 가입
- → "같이가계부에서 '{닉네임}'(으)로 함께 써요" 확인과 "닉네임은 {그룹장 닉네임}님이 정했어요"
- → [시작하기]
- 이름을 입력하는 칸은 없다.

**DB 동작**
- `accept_invite`는 그룹 초대일 때 `invitee_name`을 닉네임으로 쓴다.
- 이미 프로필이 있는 사람이어도 이 닉네임으로 바꾼다.
- 예전 방식으로 만든 초대(`invitee_name`이 비어 있음)는 Google 이름을 쓴다.

### 4.6 처음 홈 3단계

**"연결됨"의 기준**
- 그룹 구성원 중 누군가의 기기 연결(폐기되지 않은 `ingest_tokens`)에 `last_used_at`이 있으면, 즉 문자나 연결 시험이 한 번이라도 실제로 도착했으면 "연결됨"으로 본다.
- 사람마다 같은 기준으로 "내 휴대폰 연결됨" 여부도 판단한다.

| 단계 | 조건 | 홈에 보이는 것 |
|---|---|---|
| 1 | 그룹 안에 연결된 사람이 아무도 없음 | 가계부 친구 그림 + "내 휴대폰을 연결해 주세요" + 연결 순서 3칸 + [내 휴대폰 연결하기]. 그룹장과 그룹원 모두 같은 화면을 본다 |
| 2 | 한 명이라도 연결됐고, 그룹에 전체 한도가 한 번도 없음 | 한도 정하기 화면. "✓ {닉네임}님 휴대폰이 연결됐어요" + "이번 달은 얼마까지 쓸까요?" + 금액 입력 + 빠른 선택(150만·200만·250만·300만). **건너뛸 수 없다** |
| 3 | 한도가 있음 | 평소 홈 |

**한도 정하기**
- 먼저 정한 사람의 한도를 두 사람이 함께 쓴다.
- 그래서 나중 사람에게는 2단계가 나오지 않는다.

**3단계 홈의 추가 표시**
- 이번 달 결제가 없으면, 목록 자리에 가계부 친구 그림과 "잘하고 있어요! / 조금만 더 버텨봐요!", "다음 카드 결제부터 여기에 쏙 들어와요."를 보여 준다.
- 내 휴대폰이 아직 연결 전이면, 홈 맨 위에 "내 휴대폰은 아직 연결 전이에요 · 연결하기 ›" 알림을 보여 준다. 누르면 연결 안내로 가고, 연결되면 사라진다.

**"확인할 문자" 알림**
- 지금처럼 유지한다.

### 4.7 한도 바꾸기 (메뉴 "한도")

**보이는 것**
- 지금 한도
- 새 한도 입력
- 적용 시점: **이번 달부터** 또는 **다음 달부터**

**저장 방식**
- 지금 구조(`budgets`, 월별 행, 가장 최근 행이 이어짐)를 그대로 쓴다.
- 이번 달부터: 이번 달 행을 저장한다.
- 다음 달부터: 다음 달 행을 저장한다. 이번 달 행이 없으면, 이번 달 값이 바뀌지 않도록 지금 값을 이번 달 행으로 함께 남긴다.

**지난 달은 바꿀 수 없다**
- 화면에서 지난 달을 고를 수 없다.
- 서버도 이번 달보다 이전 달 저장을 거절한다.

**이번에 다루지 않는 것**
- 분류별 한도는 이번 설계에서 다루지 않는다.
- 지금의 예산 화면에 있는 분류별 기능은 그대로 둔다(내일 카테고리 설계 때 다시 본다).

### 4.8 휴대폰 연결 안내 (메뉴 "내 휴대폰 연결")

**공통**
- 한 화면에 한 단계씩 보여 준다.
- 위쪽에 진행 정도("3 / 7")와 막대를 둔다.
- 단축어 앱이나 MacroDroid에서 눌러야 할 곳을 단순한 그림에 파란 테두리로 표시한다. 그림은 CSS로 그리고, 실제 앱 캡처는 쓰지 않는다.

**기종 고르기**
- 접속한 휴대폰을 보고 자동으로 고른다(User-Agent: iPhone이면 아이폰, Android면 갤럭시).
- 첫 화면에서 바꿀 수 있다.

**카드 고르기**
- 첫 화면에서 쓰는 카드(KB국민카드·현대카드)를 고르면, 그 카드에 맞는 단계와 복사할 글자만 보여 준다.

**복사 버튼**
- 연결 코드, 카드 글자("KB국민카드", "현대"), 갤럭시용 주소·헤더·보낼 내용에 붙인다.

**마지막 단계**
- 연결 상태를 몇 초마다 확인한다.
- 시험 문자가 도착하면 "연결됐어요!"로 바뀐다.

**아이폰 7단계**
1. 카드 고르기
2. 연결 코드 복사
3. 단축어 받기(단축어 추가)
4. 연결 코드 붙여넣기(⋯ → 맨 위 글자)
5. 자동화 만들기(자동화 → + → 메시지)
6. 포함 글자를 넣고 즉시 실행 고르기(카드마다 자동화 하나)
7. 연결 확인

**갤럭시 6단계**
1. 카드 고르기
2. MacroDroid 설치
3. SMS 수신 트리거
4. HTTP 요청(주소·헤더·보낼 내용 복사)
5. 배터리 제한 없음
6. 연결 확인

**재사용하는 것**
- 지금의 `src/ledger/devices.ts`(안내 글·연결 코드·`tokenHealth`)
- 지금의 `src/components/devices/device-setup.tsx`

## 5. 배경 영상 교체 (NAS 파일)

**NAS 폴더**
- NAS 가계부 폴더 안에 `media/` 폴더를 둔다.
- 그 안에 `landing.mp4`(영상)와 `landing.jpg`(멈춘 그림)를 넣는다.
- `compose.yaml`의 app에 `./media:/app/media:ro`(읽기 전용)를 연결한다.

**영상을 내보내는 경로**
- 새 경로 `GET /media/landing.mp4`, `GET /media/landing.jpg`를 만든다.
- 정해진 두 파일 이름만 내보낸다(경로 조작 방지).
- 영상은 휴대폰이 필요한 부분만 받을 수 있게 Range 요청을 지원한다.
- 캐시는 파일 수정 시각으로 버전을 나눈다. 화면은 `?v={수정시각}`을 붙여 부르고, 응답에는 오래 캐시해도 된다는 표시를 붙인다.

**파일이 없을 때**
- 영상과 그림 없이 단색 배경으로 정상 동작한다.

**지켜야 할 것**
- 영상과 그림 파일은 git에 넣지 않는다(공개 저장소).
- 첫 적용 때 영상을 1~2MB 정도로 줄여서 넣는다(H.264, 세로 720px 정도).
- 이 Mac에는 ffmpeg가 없어서 줄이는 방법은 작업 단계에서 정한다.

**문서**
- `docs/deploy/README.md`에 영상 교체 방법을 적는다.

## 7. 테스트

**단위 테스트**
- 처음 홈 단계 판정(연결 여부 × 한도 여부)
- 카드 이름 바꾸기
- 한도 적용 달 계산(이번 달부터·다음 달부터, 지난 달 거절)
- 기종 판별
- 공유 문구 만들기

**DB 테스트**
- 닉네임 저장: 그룹 만들기, 초대 수락, 이미 프로필이 있는 경우
- 새 링크를 만들면 이전 링크가 취소되는지
- 예전 초대(닉네임 없음) 호환
- 지난 달 한도 저장 거절

**화면 테스트(Playwright)**
- 처음 화면 → 가계부 만들기 → 초대(공유 창은 흉내 내고 복사 대체 경로 포함) → 처음 홈 1단계
- 연결 → 2단계 한도(건너뛰기 없음) → 3단계 빈 목록 문구
- 연결 전 알림
- 메뉴 조건부 항목
- 영상 경로: Range 응답, 파일이 없을 때

**Google 로그인 시험**
- 화면 테스트에서 Google 창 자체는 흉내 낸다.
- 실제 Google 로그인은 운영 적용 뒤 사용자가 아이폰에서 한 번 확인한다.

**지금 있는 테스트**
- 단위 89, DB 83, 화면 30
- 바뀐 문구와 흐름에 맞게 고치고, 모두 통과해야 한다.

## 8. 적용 순서와 반영

작업 계획(writing-plans)에서 Task로 나눈다. 큰 순서는 다음과 같다.
1. 디자인 기준
2. DB·닉네임·초대
3. 처음 홈·한도
4. 연결 안내
5. 홈·메뉴
6. 처음 화면·영상 경로
7. Google 로그인

**운영 반영**
- 아래는 실제 서비스를 바꾸는 작업이라 각각 사용자 승인 뒤 진행한다.
  - 클라우드 DB 적용(백업 먼저)
  - NAS `.env`·`compose.yaml` 변경(`GOOGLE_CLIENT_ID`, media 폴더)
  - Google 콘솔 설정
  - 새 버전 태그
- 클라우드 DB 적용과 태그 push는 자동 안전장치 때문에 사용자가 직접 실행할 명령으로 준비한다.

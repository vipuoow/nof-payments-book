# 예산·카테고리 관리·기기 연결 안내 설계 (계획 3-2)

작성일: 2026-10-02
상태: 설계 확정, 구현 계획 작성 전
상위 설계: `docs/superpowers/specs/2026-10-01-nof-payments-book-design.md`, `docs/superpowers/specs/2026-10-02-screens-core-design.md`(3-1)

## 1. 목표

3-1의 원칙(앱을 자주 열지 않아도 됨)을 지키면서, 한 번 정해 두면 계속 쓰는 설정을 더한다. 예산은 한 번 정하면 매달 이어지고, 카테고리는 그룹에 맞게 정리하며, 두 사람이 각자 휴대폰에서 결제 문자 자동 전송을 스스로 설정할 수 있게 한다.

**성공 기준**

- 예산을 한 번 정하면 다음 달에도 홈에 진행률이 나오고, 다시 입력하지 않아도 된다.
- 예산의 80%를 넘은 카테고리만 홈에 경고로 보이고, 나머지는 보이지 않는다.
- 안 쓰는 기본 카테고리를 숨기면 카테고리 버튼과 jev 선택지에서 빠진다.
- 기기 연결 화면에서 기종 탭을 고르면, 복사해 붙여넣기만 하면 되는 설정값과 단계별 안내가 나온다.

**사용자가 정한 것 (2026-10-02)**

| 질문 | 결정 |
|---|---|
| 3-2 범위 | 예산, 카테고리·규칙 관리, 기기 연결 안내. 통계는 하지 않음 |
| 예산 주기 | 한 번 정하면 매달 이어짐. 바꾸면 그 달부터 적용 |
| 예산 단위 | 가족 전체 + 원하는 카테고리별 |
| 기본 카테고리 | 그룹별로 숨기기 가능. 이름은 바꾸지 않음 |
| 기기 안내 | 아이폰·갤럭시 모두. 탭으로 기종을 고르면 그 기종 안내 |

## 2. 범위

**포함**

- 홈의 예산 표시, 예산 화면(`/budget`)
- 카테고리 화면(`/categories`): 기본 카테고리 숨기기, 그룹 카테고리 추가·이름 바꾸기·삭제, 가맹점 규칙 목록·삭제
- 기기 연결 화면(`/devices`) 개편: 기종 탭, 단계별 안내, 복사 버튼, 마지막 수신 3일 경고
- 3-1에서 미룬 사소한 문제 5가지(7장)

**제외**

- 통계(월별 추이, 카테고리 비중, 사람별 비교)와 사람·카테고리 필터. 상위 설계 6장의 "통계" 화면은 만들지 않는다.
- 예산 알림(상위 설계대로 알림 없음), 사람별 예산

## 3. 화면

### 3.1 홈 예산 표시

가족 합계와 사람별 합계 아래에 둔다. 그 달에 적용되는 예산(4.1)이 하나도 없으면 이 영역을 그리지 않는다.

```
 가족 1,234,000원
 지민 650,000 · 서연 584,000
 ━━━━━━━━━━━━━━━━━━━░░░░░  예산 3,000,000원 중 41%
 1,766,000원 남음
 카페 92% · 8,000원 남음          ← 80% 이상인 카테고리만
 식비 108% · 64,000원 초과
```

- 전체 예산이 있으면 막대와 "N원 남음" 또는 "N원 초과"를 보여 준다. 사용률이 `budget_warning_ratio`(0.8) 이상이면 막대와 문구를 경고 색으로, 100% 초과면 위험 색으로 바꾼다.
- 카테고리 예산은 사용률이 `budget_warning_ratio` 이상인 것만 사용률이 높은 순으로 한 줄씩 보여 준다.
- 사용액은 그 달 거래 합계다(취소 반영, 카테고리 예산은 그 카테고리 거래만). 3-1의 합계 계산을 그대로 쓴다.
- 지난달을 보면 그 달에 적용됐던 예산으로 계산한다.

### 3.2 예산 (`/budget`)

- 메뉴(☰)에 "예산"을 추가한다.
- 맨 위 "가족 전체" 입력칸, 그 아래 보이는 카테고리(숨긴 기본 카테고리 제외)마다 입력칸. 각 칸 옆에 이번 달 사용액을 작게 표시한다.
- 입력칸에는 이번 달에 적용되는 예산이 채워져 있다. 비우면 예산 없음.
- [저장]: 값이 바뀐 칸만 이번 달(KST) 1일 날짜로 저장한다(4.1). 저장 후 홈으로 돌아간다.
- 안내 문구: "저장하면 이번 달부터 적용되고 다음 달에도 이어집니다."

### 3.3 카테고리 (`/categories`)

- 메뉴에 "카테고리"를 추가한다.
- **기본 카테고리**: 9개를 `sort_order` 순으로 보여 주고, 각각 [숨기기] 또는 [보이기]. 숨긴 것은 회색으로 표시한다.
- **우리 카테고리**: 목록과 각 항목의 [이름 바꾸기], [삭제]. 아래에 새 카테고리 이름 입력칸과 [추가].
  - 이름 규칙: 앞뒤 공백 제거, 1~20자, 기본 카테고리 이름이나 우리 그룹의 다른 카테고리 이름과 같으면 안 된다.
  - 삭제 확인 문구: "삭제하면 이 카테고리의 거래는 미지정이 되고, 관련 가맹점 규칙과 예산도 지워집니다."
  - 새 카테고리는 기존 그룹 카테고리 뒤에 붙인다(`sort_order` = 그룹 최대값 + 1, 최소 10).
- **가맹점 규칙**: "가맹점 → 카테고리" 목록(가맹점 이름순)과 각 항목의 [삭제]. 규칙이 없으면 "거래의 카테고리를 고르면 여기에 규칙이 생깁니다."
- 숨긴 카테고리는 카테고리 버튼(거래 시트), 직접 입력, 예산 화면, jev 선택지에서 빠진다. 이미 그 카테고리인 거래는 홈에 그 이름 그대로 보인다.

### 3.4 내 기기 연결 (`/devices`)

```
 [ 아이폰 | 갤럭시 ]            ← ?device=iphone(기본) | android
 1. 토큰 발급  [기기 이름____] [토큰 발급]
 2. 단계별 설정 안내 (기종별)
 3. 복사할 값
    주소     https://…/api/ingest          [복사]
    헤더     Authorization: Bearer <토큰>   [복사]
    보낼 내용 {"body": …, "source": "ios_shortcut"} [복사]
 내 기기 목록 (마지막 수신, 3일 넘으면 경고, 폐기)
```

- 탭은 링크다(`?device=…`). 잘못된 값이면 아이폰.
- 토큰은 발급 직후 한 번만 보여 준다(기존과 같음). 발급 직후에는 헤더 복사값에 실제 토큰이 들어가고, 그 전에는 `<토큰>` 자리 표시가 들어간다.
- 서버 주소는 `APP_URL` + `/api/ingest`.
- 보낼 내용의 `source`는 아이폰 `ios_shortcut`, 갤럭시 `android_macrodroid`(ingest API가 이미 받는 값).
- 기기 목록: 마지막 수신이 3일보다 오래되면 "3일 넘게 문자가 오지 않았습니다. 설정을 확인해 주세요." 경고. 받은 적이 없으면 "아직 받은 문자가 없습니다."

**아이폰 안내 (단축어 앱)**

1. 단축어 앱 → [자동화] → [+] → [메시지].
2. "메시지에 다음이 포함됨"에 `KB국민카드`를 넣는다. [즉시 실행]을 켜고 [다음].
3. [새로운 빈 단축어] → 동작 [URL 콘텐츠 가져오기]를 추가한다.
4. URL에 복사한 주소를 넣고, 방법 `POST`, 헤더에 `Authorization` = `Bearer <토큰>`.
5. 본문 `JSON`: `body` = 단축어 입력의 [메시지 내용], `source` = `ios_shortcut`.
6. 결제 후 홈에 거래가 나타나는지 확인한다.

iOS 버전에 따라 메뉴 이름이 조금 다를 수 있다는 문구를 함께 둔다.

**갤럭시 안내 (MacroDroid 앱)**

1. MacroDroid 설치 → [매크로 추가].
2. 트리거 [SMS 수신]: 내용에 `KB국민카드` 포함.
3. 동작 [HTTP 요청]: 방법 `POST`, URL에 복사한 주소, 헤더 `Authorization: Bearer <토큰>`, 콘텐츠 유형 `application/json`, 본문에 복사한 보낼 내용(문자 내용 자리에 `[sms_message]`).
4. 휴대폰 설정에서 MacroDroid의 배터리 최적화를 끈다.
5. 결제 후 홈에 거래가 나타나는지 확인한다.

**알려진 위험**: 잠긴 아이폰과 절전 갤럭시에서의 자동 실행은 아직 실기기로 확인하지 않았다(상위 설계 11장). 갤럭시는 문자 내용의 줄바꿈이 JSON 본문을 깨뜨릴 수 있다. 실기기 확인에서 문제가 나오면 ingest API가 다른 본문 형식도 받도록 따로 고친다(이 계획 범위 밖).

## 4. 데이터

### 4.1 예산

- `budgets.amount` 조건을 `> 0`에서 `>= 0`으로 바꾼다. 0은 "이 달부터 예산 없음"이다.
- 적용 예산: 카테고리(`null`은 가족 전체)마다 `month <= 보는 달`인 행 중 `month`가 가장 늦은 행의 금액. 0이면 예산 없음. 순수 함수 `effectiveBudgets(rows, month)`로 계산한다.
- 저장: 바뀐 칸만 (그룹, 카테고리, 이번 달 1일)로 upsert한다(기존 unique `nulls not distinct (group_id, category_id, month)`). 비운 칸은 0을 저장한다. 원래 예산이 없던 칸을 비운 채로 두면 저장하지 않는다.
- 기존 RLS(`budgets` 그룹 전체 권한, 카테고리 검사)를 그대로 쓴다.

### 4.2 기본 카테고리 숨김

새 테이블 `category_hidden (group_id, category_id, primary key (group_id, category_id))`.

- RLS: 내 그룹 행만 읽기·추가·삭제. 추가할 때 카테고리가 기본(`group_id is null`)이어야 한다.
- 숨김 반영 위치: 카테고리 선택지(`loadCategories`의 버튼용 목록), 직접 입력, 예산 화면, jev 분류(`categorizeTransaction`의 선택지). 거래 줄 표시용 이름 목록은 숨김과 관계없이 모두 둔다.

### 4.3 그룹 카테고리 이름

- `categories`에 그룹 카테고리 이름 고유 인덱스: `unique (group_id, name) where group_id is not null`.
- 기본 이름과 같은지는 화면 검증에서 막는다(순수 함수 `validateCategoryName`).
- 삭제는 기존 FK로 처리된다: 거래 `category_id`는 null(트리거가 출처도 null), 가맹점 규칙·예산은 함께 삭제.

### 4.4 취소·결제 카테고리 맞추기

- `ingest_sms`: 먼저 온 취소를 결제에 연결할 때, 취소의 카테고리가 없고 결제에 카테고리가 있으면 취소에도 같은 카테고리·출처를 넣는다.
- `categorizeTransaction`(jev): 결제를 분류해 저장하면, 그 결제에 연결된 취소 중 카테고리가 없는 것에도 같은 카테고리(`ai`)를 넣는다.

## 7. 3-1에서 미룬 사소한 문제

1. 미분류 문자 무시·등록 시 현재 상태가 `unparsed`인지 확인한다. 등록할 문자가 이미 처리됐으면 "이미 처리된 문자입니다."를 보여 주고 거래를 만들지 않는다.
2. 수동 거래 삭제에서 지운 행이 없으면 "저장하지 못했습니다. 다시 시도해 주세요."
3. 취소·결제 카테고리 맞추기(4.4).
4. 거래 시트: `aria-modal="true"`, 열릴 때 시트로 포커스 이동, 열려 있는 동안 배경 스크롤 잠금. 메뉴: 바깥을 탭하면 닫힘.
5. 화면 테스트의 시드 시각을 "지금으로부터 몇 분 전"으로 바꿔 자정 무렵에도 미래 시각 거래가 생기지 않게 한다.

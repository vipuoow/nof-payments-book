# + 버튼 펼침 · 문자 붙여넣기 / 직접 적기 설계

작성: 2026-10-08 · 상태: 사용자 승인(대화, "좋아, 진행해"). 저장 방식은 사용자가 "직접 추가 + 겹침 경고"를 골랐다.

**왜**: 홈의 +만 보고는 무엇을 하는 버튼인지 알기 어렵다. 또 카드 문자가 자동으로 안 들어온 결제를 적을 때, 받은 문자를 붙여 넣으면 한 번에 채워지게 한다.

## 1. + 버튼 펼침

```
평소            누른 뒤(3초)                    3초 뒤
   [+]    →   [ 결제 직접 입력 ] [×]    →        [+]
```

- +를 누르면 +가 45° 돌며 ×가 되고, 그 왼쪽으로 **[결제 직접 입력]** 알약 버튼이 0.25초에 펼쳐진다.
- **3초** 동안 아무것도 누르지 않으면 알약이 오른쪽으로 접혀 들어가고 ×가 +로 돌아온다.
- ×를 누르거나 화면의 다른 곳을 누르면 바로 접힌다. 접히는 데 0.25초.
- 알약을 누르면 새로 추가 화면(`?add=1`)이 열리고 메뉴는 접힌다.
- 동작 줄이기: 돌기·펼치기 움직임 없이 바로 나타나고 사라진다.
- 화면 읽기: + 버튼 이름은 "결제 입력 메뉴", 펼친 동안 `aria-expanded="true"`. 알약은 링크 "결제 직접 입력".

## 2. 분기 화면 (새로 추가 맨 앞)

```
×
어떻게 적을까요?

┌──────────────────────────────┐
│ 카드 문자 붙여넣기              │
│ 받은 결제 문자를 붙여 넣으면      │
│ 알아서 채워요                   │
└──────────────────────────────┘
┌──────────────────────────────┐
│ 직접 적기                      │
│ 금액부터 하나씩 적어요            │
└──────────────────────────────┘
```

- `?add=1`이면 이 화면부터 보인다. [직접 적기]는 지금의 한 칸씩 묻는 흐름(금액 → 어디서 → 분류 → 언제 → 누가)으로 간다.
- "확인할 문자 → [거래로 등록]"은 지금처럼 분기 없이 바로 미리 채운 흐름으로 간다.
- 화면을 넘어갈 때는 질문 넘김과 같은 움직임을 쓴다.

## 3. 문자 붙여넣기

```
‹  카드 문자 붙여넣기
┌──────────────────────────────┐
│ (여기에 결제 문자를 붙여 넣어요)  │   ← 여러 줄 입력칸
└──────────────────────────────┘
         [붙여넣기]                   ← 클립보드에서 가져오기
[            읽기            ]        ← 체크 버튼
```

- [붙여넣기]는 `navigator.clipboard.readText()`로 클립보드 글을 입력칸에 넣는다(아이폰은 "붙여넣기" 확인 말풍선이 한 번 뜬다). 못 읽으면 "입력칸을 길게 눌러 붙여 넣어 주세요."를 보여 준다. 입력칸에 직접 붙여 넣어도 된다.
- [읽기]를 누르면 `readPastedSms(글, 지금)`(`src/ledger/paste-sms.ts`)이 결과를 돌려준다.
  1. 국민카드·현대카드 분석기(`parseSms`)로 읽는다.
     - 승인: 금액·가게·시각을 쓴다.
     - 취소: **취소** 결과.
     - 그 밖(무시·모름): 2로.
  2. 문자 짐작(`guessFromSms`)으로 금액·가게·시각을 찾는다.
  3. 금액이 없으면 **금액 없음** 결과.
- 결과에 따라:

| 결과 | 화면 |
|---|---|
| 금액·가게·시각을 다 찾음 | 분류 규칙이 있으면 바로 마지막 "다 입력했어요" 화면, 없으면 분류 한 칸만 묻고 마지막 화면 |
| 일부만 찾음(금액은 있음) | 빠진 것만 묻고 마지막 화면 |
| 금액 없음 | "결제 금액을 찾지 못했어요. 문자를 확인하거나 직접 적어 주세요." + [직접 적기] |
| 취소 | "취소 문자예요. 원래 결제를 찾아 지워 주세요." 저장하지 않는다 |
| 빈 입력 | "결제 문자를 붙여 넣어 주세요." |

- 채우는 값: 금액·가게·시각(문자에서), 누가 = 나, 분류 = 우리 가계부의 가맹점 규칙(`merchant_rules`, 가게 이름이 같을 때). 규칙은 서버가 찾아 준다(`findRuleCategory` 서버 액션).
- 찾은 값은 지금의 미리 채운 흐름처럼 위에 차례로 떠올라 쌓인다. 마지막 화면에서 쌓인 값을 눌러 고칠 수 있다.
- 붙여 넣은 문자 원문은 서버로 보내지 않고 저장하지 않는다. 뽑은 값만 쓴다.

## 4. 저장과 겹침 경고

- 직접 추가한 거래(`kind = manual`)로 저장한다(고치기·지우기 가능).
- **붙여넣기로 온 거래만** 저장할 때 서버가 겹침을 확인한다: 같은 가계부·같은 사람·같은 금액, 시각이 앞뒤 5분 안인 결제(카드 승인 또는 직접 추가)가 있으면 저장하지 않고 그 거래를 돌려준다.
- 마지막 화면에 경고:

```
이미 들어온 결제 같아요
스타벅스 · 오늘 14:05 · 4,500원
[그래도 저장]   [닫기]
```

- [그래도 저장]은 확인 없이 저장한다. [닫기]는 새로 추가 화면을 닫는다.
- 판단 함수 `findOverlap`(같은 사람·금액, |시각 차| ≤ 5분, 취소 제외)은 단위 테스트한다.

## 6. 검사

- 단위: `readPastedSms`(국민·현대 승인, 짐작만 되는 문자, 금액 없음, 취소, 빈 글), `findOverlap`(5분 경계, 다른 사람, 다른 금액, 취소 제외).
- DB: 겹침 확인 저장이 같은 결제가 있으면 거절하고, 확인 없이(그래도 저장) 저장되는지.
- 화면:
  - +를 누르면 알약이 나오고 3초 뒤 + 하나만 남는다. ×로 바로 접힌다.
  - 알약 → 분기 → 붙여넣기에 국민카드 문자 → 마지막 화면에 금액·가게·시각·나, (규칙 있는 가게면) 분류까지 채워짐 → 저장하면 목록에 나온다.
  - 같은 결제가 있으면 경고, [그래도 저장]으로 저장된다.
  - 금액 없는 글·취소 문자 안내.
  - 분기 → 직접 적기는 지금과 같다. 확인할 문자 → 거래로 등록은 분기 없이 간다.

## 하지 않는 것

- 붙여 넣은 문자를 카드 문자 거래로 저장하기(사용자 결정).
- 직접 적기의 겹침 경고.
- 붙여 넣은 거래를 jev로 자동 분류하기(규칙이 없으면 분류를 묻는다).

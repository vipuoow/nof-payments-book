# 가계부 핵심 화면 설계 (계획 3-1)

작성일: 2026-10-02
상태: 설계 확정, 구현 계획 작성 전
상위 설계: `docs/superpowers/specs/2026-10-01-nof-payments-book-design.md` (6장 화면을 3-1·3-2로 나눔)

## 1. 목표

결제 문자가 자동으로 쌓이고, 부부는 가끔 앱을 열어 **이번 달 얼마 썼는지**와 **최근 결제가 잘 들어왔는지**만 확인한다. 평소 관리할 일이 없어야 하며, 잘못 분류된 거래는 탭 몇 번으로 고치고 그 결과를 다음 결제부터 자동으로 적용한다.

**성공 기준**

- 결제 후 아무것도 하지 않아도 홈에 거래와 이번 달 합계가 보인다.
- 카테고리가 틀린 거래는 거래 탭 → 카테고리 탭, 두 번으로 고친다. 같은 가맹점의 다음 결제부터는 고친 카테고리가 바로 적용된다.
- 미분류 문자가 있을 때만 홈에 표시되고, 없으면 아무것도 보이지 않는다.

**사용자가 정한 것 (2026-10-02)**

| 질문 | 결정 |
|---|---|
| 가장 자주 하는 일 | 이번 달 지출 확인, 최근 결제 확인. 앱을 자주 열지 않아도 되어야 함 |
| 결제 시 알림(단축어가 서버 응답을 표시) | 넣지 않음 |
| 홈 구성 | 한 화면: 합계 + 이번 달 거래 전체 (홈이 곧 거래 목록) |
| 카테고리 수정 시 학습 | 자동으로 배움(묻지 않음) |
| 디자인 | 아이폰 기본 앱 느낌 |
| 화면 테스트 | Playwright 설치, 핵심 흐름 1개 |

## 2. 범위

**3-1 포함**

- 홈(합계 + 월별 거래 목록), 거래 수정 시트, 수동 입력, 미분류 문자
- 카테고리 수정 시 가맹점 규칙 자동 학습과 같은 달 일괄 적용
- 기본 디자인, PWA(홈 화면에 추가)
- 넘어온 일: 취소 문자가 승인 문자보다 먼저 온 경우 연결, 상위 설계 문서의 `duplicate` 설명 수정
- Playwright 설치와 핵심 흐름 화면 테스트 1개

**3-2로 미룸**

- 통계(월별 추이, 카테고리 비중, 사람별 비교), 카테고리 상위 항목, 사람·카테고리 필터
- 카테고리·가맹점 규칙 관리 화면, 예산(홈의 예산 진행률·초과 배너 포함)
- 기기별 문자 전송 설정 안내

## 3. 화면

### 3.1 홈 (`/`, `/?month=YYYY-MM`)

```
 ☰                                  +
 ◀  2026년 10월  ▶
 가족 1,234,000원
 지민 650,000 · 서연 584,000
 [ 확인할 문자 2건 › ]        ← 미분류가 있을 때만
 ───────────────────────────────
 10월 2일 (금)
   카페   테스트커피 강남역점   12,300  지민  자동
   미지정 (주)케이지이니시스    45,000  서연
 10월 1일 (수)
   ...
```

- 월 이동: `month` 쿼리. 없거나 형식이 틀리면 이번 달(한국 시간). 다음 달로는 이번 달까지만 이동한다.
- 합계: 그 달 거래 금액의 합. 취소는 음수로 들어 있으므로 그대로 더한다. 사람별 합계는 그룹 구성원 표시 이름(`profiles.display_name`) 순으로 보여 준다.
- 거래 목록: 그 달 거래 전체를 날짜(한국 시간)별로 묶어 최신순으로 보여 준다.
  - 한 줄: 카테고리 이름(없으면 회색 "미지정"), 가맹점, 금액, 사람 이름, `category_source = 'ai'`이면 작은 "자동" 표시.
  - 취소 거래는 음수 금액으로 표시하고, 취소가 연결된 원래 결제는 금액에 취소선을 긋는다.
  - 거래가 없으면 "이 달에는 거래가 없습니다".
- 미분류 문자 줄: 내 그룹의 `raw_messages.status = 'unparsed'` 개수가 1 이상일 때만 표시하고 `/unparsed`로 이동한다.
- 메뉴(☰): 그룹, 내 기기 연결, 운영자(운영자만), 로그아웃. 지금 홈에 있는 링크를 옮긴다.
- 그룹이 없는 사용자: 지금처럼 그룹 상태와 "그룹 만들기"(권한이 있을 때) 안내를 보여 준다.

### 3.2 거래 수정 시트

거래를 탭하면 아래에서 시트가 올라온다(주소: `/?month=…&tx=<id>`, 뒤로 가기로 닫힘).

- 카테고리 버튼(기본 + 그룹 카테고리, `sort_order` 순, 맨 끝 "미지정"). 탭하면 바로 저장하고 시트를 닫는다.
  - 카테고리를 고르면 `set_transaction_category`(4.1)를 호출한다.
- 메모, 금액, 일시, 사람: [더 보기]를 누르면 나오는 칸에서 고치고 [저장]한다. 금액은 1원 이상 정수.
- 삭제: `kind = 'manual'` 거래만 [삭제] 버튼을 보여 준다(확인 후 삭제).
- 원문: 문자에서 온 거래는 [원문 보기]로 마스킹된 원문을 보여 준다.

### 3.3 수동 입력 (`/new`)

- 홈의 "+"로 연다. 금액, 가맹점, 일시(기본: 지금), 사람(기본: 나), 카테고리(선택, 기본 미지정).
- 저장하면 `kind = 'manual'` 거래를 만든다(기존 RLS 정책 `transactions_insert_manual`). 카테고리를 넣으면 출처는 트리거가 `user`로 기록한다. 수동 입력은 가맹점 규칙을 만들지 않는다.
- 저장 후 그 거래의 달로 홈에 돌아간다.

### 3.4 미분류 문자 (`/unparsed`)

- 내 그룹의 `unparsed` 문자를 받은 시각 최신순으로, 마스킹된 원문과 함께 보여 준다.
- [무시]: 상태를 `ignored`로 바꾼다.
- [거래로 등록]: `/new?raw=<id>`로 이동한다. 수동 입력 화면 위에 원문을 보여 주고, 사람은 문자를 보낸 사용자로, 일시는 받은 시각으로 채워 둔다. 저장하면 수동 거래를 만든 뒤 문자 상태를 `parsed`로 바꾼다.
  - 두 번에 나눠 저장한다. 두 번째가 실패하면 문자가 목록에 남아 다시 등록될 수 있다(받아들인 위험).
- 남은 문자가 없으면 "확인할 문자가 없습니다".

### 3.5 디자인과 PWA

- 아이폰 기본 앱 느낌: 시스템 글꼴(`-apple-system` 계열), 흰 바탕(다크 모드는 검정), 회색 구분선, 강조색 하나. 다크 모드는 휴대폰 설정을 따른다.
- 화면 폭 최대 480px, 모바일 우선. 금액은 오른쪽 정렬, 천 단위 쉼표, 등폭 숫자.
- PWA: `manifest`(앱 이름, 아이콘, `display: standalone`, 테마 색)와 아이폰용 `apple-touch-icon`. 오프라인 캐시(서비스 워커)는 넣지 않는다.
- 문구는 한국어 존댓말, 짧게.

## 4. 데이터

### 4.1 `set_transaction_category(p_transaction uuid, p_category uuid)`

`security definer`, `auth.uid()` 기준. 한 트랜잭션에서:

1. 거래가 내 그룹 것인지, 카테고리가 null이거나 쓸 수 있는 것(`is_my_category`)인지 확인한다. 아니면 예외.
2. 그 거래의 `category_id`를 바꾸고 `category_source`를 `user`로 한다(null이면 출처도 null).
3. 카테고리가 null이 아니면:
   - `merchant_rules`에 (그룹, 가맹점 원문) → 카테고리를 넣거나 갱신한다.
   - 같은 그룹, 같은 가맹점, 같은 달(그 거래 `occurred_at`의 한국 시간 월)에 있는 다른 거래 중 `category_source`가 null 또는 `ai`인 것을 같은 카테고리로 바꾸고 출처를 `rule`로 한다.
4. 함께 바뀐 거래 수를 돌려준다.

`user`가 직접 고른 거래와 다른 달 거래는 바꾸지 않는다. "미지정"으로 되돌릴 때는 그 거래만 바꾸고 규칙은 그대로 둔다. `authenticated`에게만 실행 권한을 준다.

### 4.2 취소가 먼저 도착한 경우 (`ingest_sms` 수정)

승인 거래를 만들 때, 같은 그룹·사용자·가맹점, 금액이 `-승인 금액`, `cancels_transaction_id`가 null이고 아직 다른 취소와 짝이 아닌 취소 거래 중 `occurred_at`이 승인 이후 60일 안에 있는 가장 이른 것을 찾아 `cancels_transaction_id`를 승인 거래로 연결한다.

- 승인에 카테고리가 없고 취소에 있으면 승인이 취소의 카테고리·출처를 이어받는다(합계 상쇄). 이 경우 승인은 이미 카테고리가 있으므로 jev 분류를 건너뛴다.

### 4.3 화면 계산

- 월 범위: 한국 시간 그 달 1일 0시 ≤ `occurred_at` < 다음 달 1일 0시. 계산은 순수 함수(`src/ledger/month.ts`)로 두고 단위 테스트한다.
- 합계·사람별 합계·날짜별 묶기도 순수 함수로 둔다. 데이터는 그 달 거래를 한 번 읽어 화면에서 계산한다.
- 읽기·쓰기는 로그인 사용자 권한(RLS)으로 한다. `service_role`은 쓰지 않는다.

## 5. 오류 처리

| 상황 | 처리 |
|---|---|
| 저장 실패(RLS 거부, 네트워크) | 시트·폼 안에 "저장하지 못했습니다. 다시 시도해 주세요". 입력값과 화면은 그대로 |
| 잘못된 `month`·`tx`·`raw` 쿼리 | `month`는 이번 달로, `tx`·`raw`는 무시(시트 닫힘, 빈 폼) |
| 다른 그룹의 거래 id | RLS로 보이지 않으므로 시트를 열지 않는다 |
| 금액이 0 이하·숫자 아님, 가맹점 빈칸 | 저장 전 폼에서 막고 이유를 표시 |

## 6. 테스트

| 대상 | 방법 |
|---|---|
| 월 범위·날짜 묶기·합계·금액 표기 | 단위 테스트(월말 자정 KST/UTC 경계, 취소 포함 합계) |
| `set_transaction_category` | DB 테스트: 규칙 저장·갱신, 같은 달 null/ai 일괄 변경, user 거래·다른 달 보존, 미지정 되돌리기, 다른 그룹 거래·카테고리 거부 |
| 취소 먼저 도착 | DB 테스트: 연결, 카테고리 상속, 이미 짝이 있는 취소는 연결 안 함 |
| 화면 흐름 | Playwright 1개: 로그인 → 홈 합계·거래 표시 → 거래 탭 → 카테고리 변경 → 같은 가맹점 거래도 바뀜 |

Playwright 로그인: 앱에는 이메일 로그인 화면이 없으므로, 테스트는 로컬 Supabase의 이메일·비밀번호 로그인으로 세션을 만든 뒤 그 세션 쿠키를 브라우저에 넣는다. 로컬에서만 실행한다.

## 7. 변경하지 않는 것

- ingest API 응답 형식(알림 없음).
- jev 분류 흐름. 규칙(`rule`)이 있으면 jev를 부르지 않는 것은 그대로다.

# 같이가계부 디자인 1차 적용 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**목표:** 설계 문서대로 디자인 기준, 처음 쓰는 사람 흐름(닉네임·파트너 초대·처음 홈 3단계·한도), 휴대폰 연결 안내, 홈, 처음 화면(배경 영상), Google 직접 로그인을 실제 앱에 넣고 운영에 반영한다.

**구조**
- 화면은 Next 16 App Router의 서버 컴포넌트를 기본으로 한다.
- 상태가 필요한 곳(영상 반복, 공유, 안내 단계, Google 버튼)만 클라이언트 컴포넌트로 만든다.
- 판단 로직은 `src/ledger/*`, `src/auth/*`의 순수 함수로 빼서 단위 테스트한다.
- DB 변경은 마이그레이션 하나에 모은다.

**기술:** Next 16.3, React 19.2, Supabase(Postgres·Auth), Tailwind 4, Vitest, Playwright

**설계 문서:** `docs/superpowers/specs/2026-10-07-design-v1-design.md`

**실행 방식:** 사용자가 승인을 위임했다(2026-10-07). Native로 진행한다. 이 대화에서 직접 구현하고, 끝에 별도 검토자가 전체를 검토한다.

## 전체 제약

- 모든 화면 문구는 한국어 해요체로 쓴다. 오류는 원인과 고칠 방법을 함께 쓴다.
- 공개 저장소에는 도메인·NAS 경로·비밀값·영상 파일을 넣지 않는다.
- 로컬 DB에 `supabase db reset`을 쓰지 않는다. `supabase migration up --local`을 쓴다.
- Next 코드를 쓰기 전에 `node_modules/next/dist/docs/`에서 해당 API를 확인한다(AGENTS.md).
- 기존 테스트(단위 89, DB 83, 화면 30)는 바뀐 문구와 흐름에 맞게 고쳐서 모두 통과시킨다.
- 닉네임: 공백 제외 1~10자, 그룹장이 정하고 바꾸는 화면은 없다.
- 그룹 인원 최대 2명(`max_group_members`). 초대 링크는 7일 동안 1회 쓸 수 있다.
- 한도: 전체 한도만 정한다. 이번 달 또는 다음 달부터 적용하고, 지난 달은 바꾸지 않는다. 처음 홈 2단계에서는 건너뛸 수 없다.

## 검토 중점

1. **휴대폰 공유 창이 없거나 거절될 때**: 링크가 복사되고 "링크를 복사했어요"가 보여야 한다. 복사까지 막히면 링크 글자를 선택 상태로 보여 준다(Task 3).
2. **예전 방식으로 만든 초대 링크**(`invitee_name`이 없음)로 가입할 때: Google 이름으로 정상 가입돼야 한다(Task 2 DB 테스트).
3. **배경 영상 파일이 없거나 Range 요청이 범위를 벗어날 때**: 처음 화면은 단색 배경으로 동작하고, 영상 경로는 404 또는 416을 돌려준다(Task 7).
4. **`GOOGLE_CLIENT_ID`가 비어 있을 때**: 지금의 리디렉트 로그인으로 동작해야 한다(Task 8 단위·화면 테스트).
5. **달이 바뀌는 순간(KST 기준)의 한도 적용 달**: 12월에 "다음 달부터"를 고르면 다음 해 1월이 되어야 한다(Task 4 단위 테스트).

### Task 2: DB — 닉네임, 초대, 처음 홈 상태

**파일**
- 만듦: `supabase/migrations/20261007010000_design_v1.sql`

- 테스트: `tests/db/design-v1.db.test.ts`

**인터페이스 (뒤의 Task가 쓴다)**
- `createGroup(db, displayName: string): Promise<Result<string>>` → `rpc create_group(p_display_name)`
- `createGroupInvite(db, inviteeName: string): Promise<Result<{token, expiresAt}>>` → `rpc create_group_invite(p_token_hash, p_invitee_name)`
- `acceptInvite(db, token, fallbackName: string)`
  - 서버가 `p_display_name`에 Google 이름을 넘긴다.
  - 그룹 초대면 DB가 `invitee_name`을 우선 쓴다.
- `getInviteStatus` 결과에 `inviteeName: string | null`을 더한다(`inviter_name`은 그대로 둔다).
- `loadSetup(db): Promise<{ anyConnected: boolean; meConnected: boolean; hasTotalLimit: boolean; memberCount: number; pendingInvite: { name: string; expiresAt: string } | null }>`
  - `rpc group_setup_status()`를 부른다.
  - 보안 정의 함수(security definer)라 파트너의 기기 연결 여부도 읽을 수 있다.

**SQL 요점**
- `alter table group_invites add column invitee_name text`
- `create_group(p_display_name)`
  - 닉네임을 다듬고, 1~10자인지 확인한다(`name_required`·`name_too_long`).
  - 기존 `create_group()` 본문과 같은 일을 한 뒤 `profiles.display_name`을 바꾼다.
  - 이전 함수는 `drop function public.create_group()`으로 지운다.
- `create_group_invite(p_token_hash, p_invitee_name)`
  - 닉네임을 확인한다.
  - 그 그룹에서 아직 쓰지 않았고 취소되지 않은 초대에 `revoked_at = now()`를 넣는다.
  - 새 행을 넣는다(`invitee_name` 포함).
  - 이전 1인자 함수는 지운다.
- `accept_invite`
  - 그룹 초대면 `v_name := coalesce(nullif(trim(g.invitee_name),''), v_name)`을 쓴다.
  - 이미 프로필이 있으면 `display_name`을 `v_name`으로 바꾼다.
  - 서비스 초대는 지금 그대로 둔다.
- `invite_status`: 결과에 `invitee_name`을 더한다.
- `group_setup_status()` returns jsonb
  - `any_connected`: 내 그룹 구성원 중 `ingest_tokens.revoked_at is null and last_used_at is not null`이 있는지
  - `me_connected`: 같은 기준으로 나
  - `has_total_limit`: `budgets`에서 `category_id is null and amount > 0`
  - `member_count`
  - `pending_invite`: `used_at·revoked_at`이 null이고 `expires_at > now()`인 가장 최근 초대의 이름과 만료일. 없으면 만료된 가장 최근 초대를 `expired: true`로 돌려준다.
- 권한
  - 새·바뀐 함수는 `authenticated`에만 실행을 허용한다.
  - `invite_status`는 `service_role`에만 허용한다.

**DB 테스트(먼저 쓴다)**
- `create_group('남편')`: 그룹을 만들고 `display_name = '남편'`이 된다. 빈 값이면 `name_required`, 11자면 `name_too_long`이다.
- `create_group_invite(h1,'아내')` 뒤에 `(h2,'아내')`를 부르면 h1이 취소된다. 그 링크로 수락하면 `invite_revoked`가 난다.
- 그룹 초대를 수락하면 `display_name = invitee_name`이 된다. 이미 프로필이 있는 사람도 바뀐다.
- `invitee_name`이 null인 예전 초대는 넘긴 이름으로 가입한다.
- `group_setup_status`
  - 처음에는 모두 false
  - 파트너 토큰의 `last_used_at`을 넣으면 `any_connected`는 true, 나의 `me_connected`는 false
  - 전체 한도를 넣으면 `has_total_limit`가 true

- [ ] 마이그레이션을 쓰고 `supabase migration up --local`로 적용한다.
